# Day31：给现有程序写最小自动化检查

日期：2026-10-13。可以跨日完成。Day30代码经AI修复后实现通过，本课让你自己证明结果，顺带巩固返回值和SQL取数，不先引入pytest。

## 今天的目标

会按“准备数据 → 调用功能 → 比较预期 → 清理”写检查；能读懂断言失败。不要只打印“通过”，也不要把错误吞掉再宣称通过。

## 学习顺序（约两小时，可调整）

1. 先读并运行day31.py，观察四节实际输出。
2. 对照讲义理解actual是实际返回值，expected是按种子数据算出的结果。
3. 一次补一个TODO；可查月度笔记、讲义和原代码。
4. 写完三组后做一次“故意错预期”实验，确认检查真的会失败，再恢复正确预期。

在仓库根目录用PowerShell：

```powershell
.\.venv\Scripts\python.exe day31\day31.py
.\.venv\Scripts\python.exe day31\homework31.py
```

## 作业与明确预期

| TODO | 准备/行为 | 预期 |
| --- | --- | --- |
| 1 月报 | 已给三笔，10月12.5+7.5，9月30 | 10月(2,20)，9月(1,30)，2000-01或其他无数据月份为(0,0) |
| 2 持久化 | 已关闭旧连接，再打开同一路径；不重复种数据 | 全部记录仍3笔 |
| 3 重跑去重 | 临时quotes表，同一名言插入两次 | 首次和再次总数都为1 |

SQL总数的读取形状参考：`conn.execute("SELECT COUNT(*) FROM 表名").fetchone()[0]`。这里表名为代码中的固定表名，不拼接用户输入。

先做TODO1即可，不要求一次做完。assert格式参考讲义，不提前提供三组完整答案。

故意错误实验：只把你自己的10月预期暂改为(2,999)，记录AssertionError和对应行号；恢复(2,20)并重新通过。不改Day30业务代码，不改真实数据库。

## 验收条件

- 三组检查真正比较了实际结果与预期，不硬编码actual。
- 关闭重开后核对持久化；检查不能因重复种数据而误通过。
- 错预期能失败，恢复后能通过；发生错误时不显示最后成功信息。
- 仅使用work下临时数据库，连接关闭后清理；不抓网站，不修改正式数据。
- 交卷：代码、完整运行结果、故意失败/恢复记录（可在文件末尾#笔记记录）。

## 关键提醒

assert是开发期检查，可被优化模式关闭，不替代业务输入校验。本课不用`python -O`。临时目录退出时清理，所以不依靠残留文件验收，靠本次查询结果与断言。

学完后在项目中做一次小变式即可，不增加长串问答。讲义已运行不表示作业完成；TODO骨架第一次报NotImplementedError是预期状态。
