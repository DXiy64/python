## 一、基础语法与数据类型

来源：Day01–02、Day09笔记。

| 写法 | 含义 | 容易混淆的地方 |
| --- | --- | --- |
| `name = "小明"` | 将变量名绑定到对象 | `=`是赋值，`==`才是比较 |
| `print(value)` | 向屏幕显示内容 | 不替函数交出业务返回值 |
| `input("提示")` | 读取一行输入，返回字符串 | 输入12，得到的是`"12"` |
| `int("12")` | 转换为整数 | `int("abc")`会触发ValueError |
| `float("12.5")` | 转换为浮点数 | 浮点数不能精确表示很多十进制小数 |
| `f"金额：{money:.2f}"` | 组合文字并将金额显示为两位小数 | 显示格式不等于修复精度 |
| `text.strip()` | 去掉字符串两端的空白字符 | 不只去换行，也不去掉中间空格 |
| `text.isdigit()` | 判断非空字符串是否全部为数字字符 | 不能检查负数、小数或真实手机号有效性 |

常用数据：字符串`str`、整数`int`、浮点数`float`、布尔值`bool`、列表`list`、字典`dict`、元组`tuple`、集合`set`和`None`。

`None`表示没有值的一种明确状态，不是数字0、空字符串或空列表。判断通常写`value is None`。

`random.randint(a, b)`包含两端。变量名不能以数字开头，也不能用关键字；Python允许部分Unicode字符，但学习时优先清晰的英文名称与下划线。

## 二、列表、字典与数据形状

来源：Day03–04、Day08笔记；Day30近期练习。

先问“这个变量是什么类型”，再决定用位置还是键取值。

```python
records = [
    {"category": "餐饮", "money": 12},
    {"category": "交通", "money": 8},
]
```

| 表达式 | 得到什么 |
| --- | --- |
| `records` | 整个列表 |
| `records[0]` | 第一笔字典 |
| `records[1]["money"]` | 第二笔的金额8 |
| `for record in records` | 每轮让record指向其中一笔字典 |
| `record[1]` | 查字典的整数键1；示例没有它，会KeyError |

列表：按索引取值，索引从0开始；`[-1]`取最后一个；`append()`增加一个元素；`len()`取元素数量；`max()/min()`取最大/最小，空列表需要另行处理。

字典：按键取值；`d[key]`缺键会KeyError；`d.get(key, default)`缺键返回默认值，不是“回车”；`key in d`检查键；`d.items()`提供键值对视图，可用于遍历。

```python
for name, phone in contacts.items():
    print(name, phone)
```

字典相同键不会同时保存两个值，再赋值会覆盖。改名不是原地改变某个键，而是建立新键并移除旧键；实际业务还要处理新键已存在的情况。

Day21账本要求“列表里的每个元素是一笔字典”。读取失败的默认值要与该形状一致：返回`[]`，不能随意换成`{}`。

## 三、条件、循环与执行顺序

来源：Day02–03、Day06笔记；Day30诊断。

比较表达式产生`True/False`，金额累计是另一步。条件不成立时跳过对应代码，不会自动清零或输出0。

```python
total = 0
for record in records:
    if record["category"] == "餐饮":
        total += record["money"]
```

| 语句 | 作用范围 |
| --- | --- |
| `if/elif/else` | 选择满足条件的分支 |
| `for` | 依次处理可迭代对象的元素 |
| `while` | 条件为真时重复 |
| `continue` | 跳过当前这轮剩余代码 |
| `break` | 结束当前最内层循环 |
| `return` | 结束整个当前函数，并交出返回值 |

空列表会让`for`执行0轮，但**循环后面的代码仍会执行**。缩进决定代码属于哪个块，通常每级4个空格。

## 四、函数、参数与返回值

来源：Day04、Day09、Day18作业修正；Day30综合练习。

每个函数先明确三件事：输入、输出、副作用。副作用包括打印、改数据、写文件、请求网络等。

```python
def category_report(records, category):
    count = 0
    total = 0
    for record in records:
        if record["category"] == category:
            count += 1
            total += record["money"]
    return count, total
```

`records/category`是形参；调用时传入的是实参。`return count, total`返回一个元组；调用者可以解包：

```python
count, total = category_report(records, "餐饮")
print(count, total)
```

这个函数不打印、不修改数据；无匹配或空列表返回`(0, 0)`。金额求和结束后再返回，不能在第一轮就结束。

```python
def add(a, b):
    print(a + b)

result = add(2, 3)  # 屏幕显示5，但result是None
```

**打印了结果，不等于返回了结果。** 函数执行到结尾仍未遇到带值的return，或使用裸`return`，就返回None。

调用必须带括号：`parse(html)`会运行；仅写`parse`只是取出函数对象。接住返回值才能交给下一步：`rows = parse(html)`。

优先使用传入参数，不偷偷遍历全局数据。Day18旧错误中，`to_digits(s)`没有接住返回值，清洗后的字符串便没有进入下一步。

函数定义不是执行函数体。真正调用时，该名字必须已经可用；辅助函数可以写在main定义之后，只要它在main被实际调用前已定义。

## 五、变量引用与数据修改

来源：Day30对话诊断补充，解决原笔记未覆盖的误区。

```python
a = {"money": 12}
b = a
b["money"] = 100
```

a与b指向同一个字典，没有复制；最后一行修改共同对象，因此`a["money"]`也是100。

对照：

```python
a = {"money": 12}
b = a
b = {"money": 100}
```

最后一行只让b指向新字典，原字典未修改，因此a中的金额仍12。

| 左边写法 | 改变什么 |
| --- | --- |
| `b = ...` | b这个名字指向的对象 |
| `b["money"] = ...` | 当前字典中的值 |
| `record["money"] += 1` | 如果record指向列表里的字典，原记录随之改变 |

“列表长度没变”不代表内容没变。遍历本身不必修改数据，但循环体完全可以修改对象。`dict.copy()`是浅拷贝，嵌套对象仍可能共享；目前先分清赋值与复制，不急着扩展深拷贝。

## 六、从需求设计工具类

来源：Day10–13笔记与作业；Day30类设计讲解。

类适合把一组状态与围绕该状态的操作组织起来。没有共享状态或职责很简单时，普通函数即可，不强制写类。

写作顺序建议：**需求 → 数据形状 → 长期状态 → 方法输入输出 → 实现一个方法 → 验证 → 接菜单**。

| 记账需求 | 可设计的方法 | 输入/返回 |
| --- | --- | --- |
| 准备连接和表 | `__init__` | 数据库路径；初始化状态 |
| 添加一笔 | `add` | 金额/分类/备注；接口可约定新增ID |
| 查看记录 | `list_records`或当前`show` | 推荐返回记录列表；当前show打印 |
| 月报 | `month_report` | 月份；返回`(count, total)` |
| 删除 | `delete` | ID；可约定返回是否成功 |
| 关闭 | `close` | 释放连接 |

这些是设计选择。当前代码的add/delete仍打印提示，不将表中推荐接口冒充已实现接口。

```python
class Ledger:
    def __init__(self, path):
        self.conn = sqlite3.connect(path)

    def month_report(self, month):
        count, total = self.conn.execute(
            "SELECT COUNT(*), SUM(money) FROM ledger WHERE time LIKE ?",
            (month + "%",),
        ).fetchone()
        return count, total if total is not None else 0
```

这是展示结构的片段，未包含建表，不能单独当完整项目运行。

- `self`是普通参数名的约定，实例调用时由Python传入当前对象；不是关键字。普通实例方法通常第一参数为self。
- `self.conn`是对象长期状态，多方法共用；count/total是本次查询局部结果，不必加self。
- `__init__`用于初始化，不应返回业务结果；没有初始化需求可不自行定义。不要塞菜单、全部爬虫与日报动作。
- `__len__`用于支持`len(book)`，需返回非负整数；只有“长度”语义明确时才写。
- `__str__`需返回字符串，供`str(book)`或`print(book)`使用；不会自动打印。
- 调用普通实例方法通常是`book.add(...)`，不是无条件用`Ledger.add(...)`；book是实例，Ledger是类。
- 方法排列顺序不决定运行顺序，调用才决定；每个类不必都有load/len/str。
- `class Friend(Contact)`是继承；`super().__init__(...)`可复用父类初始化；同名方法可覆盖；同一调用接口对应不同对象行为是多态。继承按需要使用，不必为了复用几行代码强行添加。

## 八、文件、JSON、CSV与路径

来源：Day05、Day07、Day09–10、Day17、Day22–23笔记与任务。

| 操作 | 作用 | 风险/条件 |
| --- | --- | --- |
| `open(path, "r")` | 读取 | 文件缺失可能报错 |
| `open(path, "w")` | 新建或清空重写 | 可能覆盖原内容 |
| `open(path, "a")` | 末尾追加 | 不适合直接把多个完整JSON文档拼在一起 |
| `with open(...) as f` | 结束时关闭文件 | f是自选变量名 |
| `read()/readline()/readlines()` | 全文/下一行/剩余各行列表 | 大文件可逐行遍历 |

`json.dump(data, f)`写入，`json.load(f)`读出。data不只可以是字典，也可以是列表等JSON兼容结构；读出什么类型取决于文件内容。`ensure_ascii=False`保留可读Unicode字符，`indent=2`改善排版，文件仍应明确UTF-8编码。

```python
HERE = Path(__file__).parent
OUT = HERE / "out"
OUT.mkdir(parents=True, exist_ok=True)
path = OUT / "report.txt"
path.write_text("内容", encoding="utf-8")
```

路径的`/`是Path拼接操作，不是除法。Path与os.path都可用，当前课程优先Path，不将另一个写法判错。write_text不会自动创建父目录。

CSV用csv模块，不手拼逗号。Windows/Excel场景常用`encoding="utf-8-sig", newline=""`；DictWriter需匹配fieldnames，默认多余字段会报错。使用reader统计CSV逻辑行，不靠简单数换行，因为字段可能含换行。

保存整本JSON时，传完整数据再用w重写；否则可能丢历史记录。删除/修改后确认存档，并重新启动验证，不只看内存结果。

## 十、正则、日期与分类统计

来源：Day17–18、Day21–22、Day24笔记与任务。

| 工具 | 目的 |
| --- | --- |
| `re.search(pattern, text)` | 找首个匹配，返回匹配对象或None |
| `re.findall(pattern, text)` | 收集匹配；分组会影响返回形状 |
| `re.sub(pattern, replacement, text)` | 返回替换后的新字符串 |
| `re.fullmatch(pattern, text)` | 整串格式校验 |
| `re.match(...)` | 从开头匹配，适合前缀需求 |

`r"\d"`原始字符串方便表达正则反斜杠；`\d`数字字符、`\D`非数字、`+`一次或多次、`?`零或一次、`{1,2}`一到两次、`()`分组。

金额模式`r"\d+(\.\d{1,2})?"`检查格式，仍需金额大于0；若只接受ASCII数字可用`[0-9]`。正则通过不代表业务值合法，例如日期2026-02-31需要日期解析进一步判断。

`datetime.now().strftime("%Y-%m-%d %H:%M")`生成时间字符串；`strptime`把符合指定格式的字符串解析为日期时间。固定格式下`text[:7]`可取年月，格式不固定时不能盲切。

Counter统计出现次数，不自动按记录金额求和；`defaultdict(float)`可用于分组金额累加。作者排行是数次数，分类金额是加金额，先分清统计对象。

整数分或Decimal用于更明确的金额规则；当前float/SQLite REAL是教学简化。round和显示两位小数不能保证精确十进制计算。

## 十一、SQLite与SQL

来源：Day24–26、Day27–29笔记；Day30修复。

```text
连接数据库 → 准备表 → 参数化执行 → 取结果或提交 → 关闭
```

| SQL | 职责 |
| --- | --- |
| `CREATE TABLE` | 定义表结构 |
| `INSERT` | 添加 |
| `SELECT ... WHERE ...` | 查询并筛选 |
| `UPDATE ... WHERE ...` | 修改选定记录 |
| `DELETE ... WHERE ...` | 删除选定记录 |
| `ORDER BY` | 排序，不是筛选 |
| `GROUP BY` | 分组计算 |
| `LIMIT` | 限制结果数量 |
| `COUNT(*)` | 统计行数 |
| `SUM(money)` | 金额求和 |
| `COUNT(DISTINCT author)` | 统计不同的非NULL作者 |

参数化传值，不能用f-string拼用户值；`?`主要用于值，不直接替代表名/列名。

```python
conn.execute("SELECT * FROM ledger WHERE id = ?", (record_id,))
```

单元素元组需要逗号：`(record_id,)`；`(record_id)`只是括号。execute返回Cursor，不是自动得到一个数字。

| 读取 | 返回形状 |
| --- | --- |
| `fetchone()` | 下一行元组，没行时None |
| `fetchall()` | 剩余行的列表，没行时[] |
| `fetchmany(n)` | 最多n行，不保证一定有n行 |
| `fetchone()[0]` | 已确认存在的一行里的第一列 |

不带GROUP BY的聚合查询，即使没有匹配记录，`COUNT(*), SUM(money)`通常仍返回一行`(0, None)`；它不同于普通查询无行时fetchone返回None。

```python
count, total = conn.execute(
    "SELECT COUNT(*), SUM(money) FROM ledger WHERE time LIKE ?",
    (month + "%",),
).fetchone()
return count, total if total is not None else 0
```

本课程约定month为YYYY-MM、time为固定格式；前缀筛选基于这个约定。面向更复杂的数据可考虑明确日期范围。

写操作按连接事务模式提交；关连接不等于自动提交。当前默认连接按显式commit管理；`with conn:`管理事务成功提交/失败回滚，**不自动关闭连接**。课程主入口仍用finally关闭。

删除可先查记录或检查影响行数；不存在不能误报成功。`rowcount`可判断相关写操作影响行数，SELECT的rowcount不能当查询总数；`total_changes`是连接累计值，不能直接当本轮新增。

主键保证唯一；`INSERT OR IGNORE`可跳过冲突，但也可能忽略其他约束问题，不能当作全能数据校验。text作为名言唯一键是本项目选择，不是所有采集项目通用设计。

初学多线程时不要随意跨线程共享连接。Python默认连接有同线程检查；SQLite线程模式与安全同步更复杂，不能简单记成所有连接永远线程不安全。

## 十二、请求、解析与日报

来源：Day08、Day27、Day29笔记；Day28翻页课程与Day30日报实现。

当前完整流程：

```text
fetch_page(n) → HTML字符串
parse(html) → [(text, author, tags), ...]
crawl(conn) → 去重入库，返回本轮新增条数
stats/top_authors → 数据库统计
check_counter → 内存计数与SQL排行对账
write_report/export_csv → 文件路径与行数
main → 调用、显示、失败处理、关闭连接
```

- requests.get返回Response，不是直接返回HTML；`.text`取文本；`.json()`解码JSON，其结果可能是字典、列表或其他JSON类型，也可能解码失败。
- timeout限制连接/读取等待，不是整个任务严格在该秒数内完成；无响应/网络异常需要处理。
- raise_for_status检查HTTP错误；状态成功不保证HTML结构符合预期。
- BeautifulSoup解析字符串；select返回匹配节点集合，select_one可能返回None，get_text获取节点文本。不要把节点集合再次当HTML字符串传入。
- 本地保存HTML可以离线调试，避免每次修解析都重新请求；联网检查与解析检查分开。
- 翻页有明确上限与间隔，去重需唯一键；不能靠每次删除数据库伪造重跑成功。
- 作者数与作者次数不是一回事；排行并列时统一次数降序、作者名升序，SQL与Counter使用同一规则。
- 日报明确编码、先建目录、名称带日期和时间；同名可能覆盖，当前还加微秒减少碰撞。
- 抓取失败/空解析明确报错，不生成看似成功的空日报。当前实现先抓齐本轮再入库；这是小规模两页任务的选择。

Day30实测样本：20条、15位作者、Albert Einstein 4条、CSV21行；重跑新增0。网站可能变化，应重算预期，不在业务代码硬编码这些数字。该实现由AI授权修复，运行通过不代表学员已独立写出。

## 十三、异常、调试与验证

来源：Day06笔记、Day19练习与Day30断言练习。

| 错误 | 优先检查 |
| --- | --- |
| NameError | 名字是否定义、拼写、作用域 |
| TypeError | 类型、参数数量、方法是否缺self |
| KeyError | 字典有没有该键，是否误用数字位置 |
| IndexError | 列表索引是否越界 |
| ValueError | 转换或解析的值是否合法 |
| AttributeError | 对象有没有该属性，是否其实是None |
| FileNotFoundError | 路径/工作目录/文件是否存在 |
| ZeroDivisionError | 除数是否为0 |

先读traceback末尾的类型与消息，再找自己文件的相关调用行。能猜原因不等于证实，查看实际类型、变量值和执行路径。

`try/except`只处理打算应对的错误；`raise`交出异常；`finally`做必要清理。Exception涵盖大多数常规异常，不是所有异常的根类，SystemExit/KeyboardInterrupt等不在它下面。

`print`用于临时观察；`breakpoint()`暂停检查；logging记录时间、级别和错误，`logging.exception()`可保留堆栈。不要吞掉异常再假装成功。

```python
assert category_report([], "餐饮") == (0, 0)
```

assert成立不显示，失败抛AssertionError。它适合学习时检查预期；Python优化模式可关闭assert，因此不能替代正式用户输入校验。

验收覆盖正常、空数据、无匹配、重复运行、跨月、重启持久化及关键失败。用隔离副本或临时库，不污染真实数据；验证期望根据种子数据计算，不只看“运行没报错”。
