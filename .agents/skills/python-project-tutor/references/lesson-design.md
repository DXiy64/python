# 新课设计检查

在生成讲义、作业或审查课程时读取；具体顺序与状态始终取自仓库文档。本文件只规定交付检查，不维护固定日程，也不提供学员当前作业答案。

## 交付内容

按任务需要选择文件，不为凑格式新增文件：讲义、TODO骨架或需求任务书、必要的同目录辅助模块与样本。各文件应能回答：

| 项目 | 必须说明 |
| --- | --- |
| 主要目标 | 本单元解决什么问题；哪些只是辅助，哪些是选学 |
| 前置 | 已学来源或当天提供的小例子；对象、参数和返回值的实际类型 |
| 调用链 | 入口→调用函数→返回结果→显示；谁创建和关闭资源 |
| 学员任务 | 要实现的接口、输入输出、允许修改的范围；TODO保留 |
| 文件 | 随课输入样本、运行生成输出、临时验证文件分别在哪里 |
| 环境 | 解释器、依赖安装名及命令、启动目录和命令 |
| 验收 | 固定样本与人工可核算的预期；正常、边界、关键失败 |
| 节奏 | 约两小时学习需几次；必要前置可跨日，不以编号强行赶进度 |

普通练习可给接口；从零/迁移项目给需求与样本，由学员先设计两三个职责。辅助模块完整提供，目标实现保留；不把教师参考答案放入学员目录，也不要求凭记忆重写所有旧模块。

## 发布新课前实际验证

1. 读取当前需求和种子数据，独立计算预期值；不能用与被测实现相同的SQL或同一个错误函数作为“预期”。
2. 将当天目录复制到work下唯一位置，在副本使用固定样本运行。清除PYTHONPATH中的原仓库路径，以干净工作目录运行，确认未通过全局路径偷用旧day文件；必要时检查导入模块的来源。
3. 讲义所有章节实际执行；有意的失败演示要被接住并说明。导入工具/讲义模块时无菜单、网络、写文件等副作用。需要交互的示例提供有界输入并检查覆盖。
4. 核对骨架保留目标TODO，未实现路径明确。NotImplementedError或未实现返回值导致的断言失败记录为待完成；ModuleNotFoundError、缺样本、错误路径等仍需修复，不能统称TODO预期失败。
5. 验证产出与正式数据隔离；按需忽略out目录/临时数据库。目录自包含检查不要求复制Python标准库、第三方库或.venv。
6. 外部服务不可用时提供本地替代；联网结果另记。固定样本的结果不能冒称真实网站当前结果。

教师为验证任务可在work中运行参考实现，不能把它作为学员作业或学员独立证据。已明确保留的历史例外写清范围，不用未来标准追溯否定旧验收。

## 概念正确性与适用条件

- 类用于组织需要共享的状态和职责；__init__、__len__等在需要相应行为时出现。对象属性数量不等于self赋值行数，循环和重复赋值都可能改变对应关系。
- 名字绑定与对象内容分开：from导入也可共享同一个可变对象，不是深复制；重新绑定名字与修改对象要分别演示。
- 存储后重建对象可能读到原数据，不能断言“对象放循环内就一定丢数据”；按实际持久化实现验证。save/commit放在哪一层取决于接口与事务责任。
- assert是开发检查，优化模式可能移除；用户输入和业务错误用明确的条件/异常处理，不把assert当正式输入校验。
- 有效性与效率分别验证；已有唯一约束可能已建索引，先检查实际查询计划，再选择索引示例。小样本时耗不能推广为普遍加速倍数。
- 正则校验、日期合法性和手机号规则依需求决定，不把某课样本变成通用业务规则。只捕获计划处理的异常，不把except Exception当统一修复。
- 未激活环境也可显式调用虚拟环境解释器；系统Python可能已装同名库，因此“退出环境必定导入失败”不是隔离验收标准。

## 维护课程时

先查实际学习证据，区分“已讲/已实现/验收/帮助/迁移”。移动核心知识须同步ROADMAP、覆盖表、README摘要与必要的能力记录；新工具的前置必须安排在使用前。避免多套教材、多个框架与全部进阶主题累加到同课。

保留原始代码和笔记。审查只记录发现与修正；未完成作业仍待完成，不生成下一课，不因检查文档或验证讲义触发提交推送。新的验收证据需要实际作业检查，不能由文档一致性检查代替。
