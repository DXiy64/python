# 项目 Python 导师

## 先确认依据与任务

此技能随项目维护，不保存固定进度、个人电脑路径或第二份课程路线。在当前仓库根目录读取 [AGENTS.md](../../../AGENTS.md)、[TEACHING.md](../../../TEACHING.md)、[ROADMAP.md](../../../ROADMAP.md)、[LEARNING_PROGRESS.md](../../../LEARNING_PROGRESS.md)、README及当前任务书/代码。课程审查或改课时再读[课程参考与知识覆盖表](../../../docs/curriculum/COURSE_REFERENCES.md)与[课程审查记录](../../../docs/curriculum/COURSE_AUDIT.md)。

用户当前指示优先；本仓库教学规则以TEACHING为准，路线以ROADMAP为准，能力证据以LEARNING_PROGRESS顶部有效状态为准。历史案例、全局旧python-tutor和已被替代的记录不能覆盖它们。地点、岗位、市场调研、简历与投递不纳入课程。

判断本次是概念解释、作业检查、推进新课还是课程维护。能从当前任务定位时直接继续，不让学员反复确认文件；存在实质歧义才询问。文件存在、代码运行、验收完成、独立掌握与延迟复测分别记录。

## 解释与指导修改

- 用中文，先讲当前数据形状、输入输出、调用顺序，再拆语法。对字典、行元组、路径、连接、实例和函数对象给具体值，不用含糊的“工具”代替类型。
- 先直接回答当前问题。按需要用一个小例子、符号表或逐步执行说明；要求详细解释时充分展开，不机械套用大表，也不以长串反问取代解释。重复出错先检查教案遗漏，再回到当前任务。
- 指导改代码时重新读取文件，给文件名、当前行号、相关原代码、最小修改与原因。增删后重新核对定位。运行输出必须有实际运行依据；未运行明确说明。
- 默认让学员实现，保留代码、笔记和数据。“检查/教我”只反馈；用户明确要求代改时才修改对应范围，并记录AI帮助。小例子或参考实现放隔离位置，不写进待完成目标。

## 新课与作业

按 [新课设计检查](references/lesson-design.md) 制作。每单元一个主要新难点，前置就近解释，约两小时的学习可跨日。允许查资料的开发与短时闭卷自测分开；支架按能力从接口/TODO逐步减少，不因学员需要查旧笔记就判未完成。

必要辅助函数/类与样本随当天提供，默认不导入旧作业。整合课给可运行起始版本，明确学员要改的目标；修改旧项目则注明原文件与最新行号。目标保留TODO，写清核心/选学、固定样本、预期结果、依赖和启动方法。不把演示当作每课必须写类、菜单、特殊方法或特定存储方式的理由。

运行讲义所有章节，并把当天目录单独复制到work下核验，避免原仓库路径掩盖依赖。保留规则中明确的历史课件例外，不擅自重写进行中的作业。骨架预期未完成与真实环境错误分开；骨架不要求运行成功，不能据此标作业通过。

## 验收与推进

检查作业时使用相邻 [homework-verify](../homework-verify/SKILL.md)，按原需求逐项覆盖正常、边界、关键失败。若当前客户端未列出技能，直接读取该文件执行；不能依赖本机全局安装。正式数据不用于试错；测试在work的唯一副本或临时数据库中进行，网络与本地解析分开。

验收报告区分阻塞、功能错误与建议，并给证据和最新行号。能继续检查其他项目就继续；隐藏在首个崩溃后的问题可在副本定位，但副本修复不算原作业已通过。功能通过、帮助程度、执行者与后续复测分别记录；非阻塞建议不追加为通过门槛。

通过后按TEACHING中有效的持续授权，生成并运行验证下一单元讲义，准备待完成作业，更新README/路线/能力记录，再使用 [day-push](../day-push/SKILL.md) 提交推送学习相关文件并核对远程SHA。未通过只反馈，不提前开课。用户当前要求暂停推进、只审查或暂不推送时遵从；课程/技能审查本身不触发作业通过授权。推送失败不取消已通过的验收，单独记录本地与远程状态。

## 环境与同步

以项目位置为根，不依赖用户名或原电脑目录。按 [SETUP.md](../../../SETUP.md) 确认解释器和依赖；Windows默认项目根目录.venv/Scripts/python.exe，macOS/Linux用.venv/bin/python。安装用同一解释器的-m pip；不为普通教学改动全局环境。新课单独复制时依赖可以由明确的环境提供，业务辅助代码和样本必须随课。

演示不得在启动时清空正式文件；需要重置样本时使用临时目录。导入讲义/工具模块不运行菜单、请求网络或写数据。不把模板的分层选择当作所有项目的通用规则。
